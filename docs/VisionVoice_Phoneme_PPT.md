# VisionVoice 简介

## AR英语学习应用的端侧AI发音评估

- **核心目标**：零网络延迟、高隐私安全的专业级发音评估
- **技术方案**：端侧离线推理，无需网络连接
- **应用场景**：AR物体识别 → 单词学习 → 发音练习

# 面临的三大核心挑战

## 🔴 挑战一：模型领域错位 (Domain Mismatch)

**问题**：ASR模型输出字母，评估基准使用音标

```
输入音频 → Wav2Vec2-base → "A-P-P-L-E" (字母)
标准答案 → CMU Dict     → "AE P L" (Arpabet音素)
                ↓
        无法对齐，全局 Substitution
```

---

# 面临的三大核心挑战

## 🔴 挑战二：异构数据源符号域冲突

**问题**：Unicode IPA vs ASCII Arpabet 字符不匹配

```
词典路径 (标准答案)：ɹ, æ, ɔ (Unicode 国际音标)
AI模型路径 (识别结果)：r, ae, ao (ASCII 音标)

"ɹ".equals("r") → false ❌
即使发音完全正确，系统判定为错读！
```

---

# 面临的三大核心挑战

## 🔴 挑战三：声学物理干扰

**问题**：清塞音(/p/, /t/, /k/)气流冲击麦克风

```
用户发音：/k/ → 标准音标 [k]
模型识别：[hh] (更接近哈气声)

物理原因：高压气流瞬间释放 → 非线性失真
         AI提取的特征偏离了声带振动
```

# 3.1 AGC自动增益控制

## 防"AI幻觉"拦截机制

```
问题：用户未发声或距离极远时
      模型将纯背景噪音解码为无意义音素碎片
```

**算法实现**：
```
1. 计算PCM数据峰值振幅
2. if 振幅 < 0.015:
       直接拦截推理 → 判定为全局漏读
   else:
       执行归一化处理 → 确保微弱特征被捕获
```

---

# 3.2 CTC解码去噪

## 过滤非发音特征

**CTC输出包含的杂质符号**：
| 符号 | 含义 |
|------|------|
| `h#` | 静音帧 |
| `spn` | 环境杂音 |
| `[UNK]` | 未知符号 |

**解决方案**：硬编码过滤器，实时剪枝剔除杂质

## 核心突破：双重归一化架构

---

# 4.1 跨服聊天的"巴别塔难题"

## 现象：完全正确的发音被判定为错读

```
UI显示：
┌─────────────────────────────┐
│  标准音标: i                │  ← 完全匹配
│  识别音标: i                │  ← 完全匹配
│  判定结果: ❌ 错读 (标红)    │
└─────────────────────────────┘
```

**根本原因**：Unicode与ASCII编码不同，Java字符串比较失败

---

# 4.2 双层翻译机制

## 架构重构：彻底剥离比对逻辑与渲染逻辑

```
        ┌─────────────────────────────────┐
        │         状态机 (State Machine)   │
        └─────────────────────────────────┘
                        ↑
    ┌───────────────────┼───────────────────┐
    ↓                   │                   ↓
Level 1             Level 2             Level 3
底层降维           对齐运算           表层升维
(Normalize        Needleman-Wunsch     (To Standard
 for Compare)      Alignment)          IPA)
    ↓                   │                   ↓
Arpabet           特征序列           Unicode
字节码            比对打分           IPA渲染
```

---

# 4.3 双重归一化详解

## 底层降维 vs 表层升维

| 层级 | 输入 | 输出 | 目的 |
|------|------|------|------|
| **底层降维** | Unicode IPA `ɹ, æ, ɔ` | ASCII Arpabet `r, ae, ao` | 统一计算平面 |
| **表层升维** | ASCII Arpabet `ae, ao` | Unicode IPA `æ, ɔ` | 专业UI展示 |

**核心思想**：算法用粗糙的Arpabet计算，UI显示专业的国际音标

# 5.1 Needleman-Wunsch全局对齐

## 定制化序列对齐算法

**问题**：用户发音长度 ≠ 标准发音长度（吞音或多读）

**算法来源**：生物信息学DNA序列比对

| 权重参数 | 分值 | 说明 |
|----------|------|------|
| MATCH | +1.0 | 完全匹配 |
| FLAW | +0.5 | 发音瑕疵 |
| MISMATCH | -1.0 | 错读 Substitution |
| GAP | -1.0 | 漏读/多读 |

---

# 5.2 对齐矩阵示意

## 标准序列 vs 用户序列

```
标准音素:   A    E    P    L
用户音素:   A         P    L

对齐结果:
A    [GAP]  P    L
↓     ↓     ↓    ↓
A → MATCH ✓  P → MATCH ✓  L → MATCH ✓
惩罚: GAP(-1) × 1 = -1
最终得分: (3 - 1) / 3 = 0.67
```

---

# 5.3 非线性评分曲线

## 基于教学反馈心理学的分段映射

```
准确率 0.0 ─────────────── 0.5 ─────────────── 0.8 ─────────── 1.0
        │                  │                  │               │
分数    0 ─────────────────┴──────────────────┴─── 100 ─────── 100

分段策略：
├─ < 0.5:  严格惩罚区 (0-59分)
├─ 0.5-0.8: 进步空间大 (60-89分) ← 激励学习
└─ ≥ 0.8:   优秀鼓励区 (90-100分)
```

# 第六部分

## 声学容错矩阵

---

# 6.1 物理抗噪：爆破音气流干扰

## Plosive Puff Effect 解决方案

**现象**：`/k/`, `/p/`, `/t/` 被识别为 `/hh/`

```
物理机制：
用户发音清塞音 → 瞬间释放高压气流
              → 冲击手机麦克风振膜
              → 产生非线性物理失真
              → AI提取特征偏离声带振动
```

**工程解决**：硬编码豁免路径，`k → hh` 判定为完全匹配 ✅

---

# 6.2 SLA理论分级惩罚

## 基于Munro & Derwing (1995) 第二语言习得理论

| 等级 | 类型 | 判定 | 分数 | 示例 |
|------|------|------|------|------|
| **一级** | 完全豁免 | Ignored → Match | 100分 | 长短元音细微偏差 |
| **二级** | 发音瑕疵 | Flaw | 60分 | 梅花音张口不足 |
| **三级** | 严重错读 | Substitution | 0分 | 破坏语义的音素 |

---

# 6.3 三级容错矩阵总览

## 完整的容错体系

```
┌─────────────────────────────────────────────────────┐
│              三级声学容错矩阵                         │
├─────────────────────────────────────────────────────┤
│  Level 1: 完全豁免 (Intelligence > Accent)         │
│  ├─ 清浊音混淆: /b/ vs /p/                          │
│  ├─ 长短元音: /i:/ vs /ɪ/                           │
│  └─ 判定: Match (满分)                              │
├─────────────────────────────────────────────────────┤
│  Level 2: 发音瑕疵 (保护学习信心)                    │
│  ├─ 梅花音张口不足: /æ/ 偏向 /ɛ/                    │
│  ├─ 平翘舌不分: /s/ vs /ʃ/                          │
│  └─ 判定: Flaw (0.5分)                              │
├─────────────────────────────────────────────────────┤
│  Level 3: 严重错读 (语义破坏)                        │
│  ├─ 音素完全替换: /r/ → /l/                         │
│  └─ 判定: Mismatch (0分)                           │
└─────────────────────────────────────────────────────┘
```
