# VisionVoice 端侧发音评估系统：核心算法演进与架构重构实录

**文档版本**：v2.0 (Core Algorithms Edition)
**项目模块**：Android 端侧 AI 离线发音诊断 (Wav2Vec2-XLS-R)
**核心技术栈**：ONNX Runtime, Needleman-Wunsch 动态规划, CTC 解码, 双重归一化 (Double Normalization)

---

## 一、 摘要 (Abstract)

VisionVoice 致力于在移动端设备上实现"零网络延迟、高隐私安全"的专业级发音评估。在系统构建过程中，面临了模型领域错位（Domain Mismatch）、异构数据源符号域冲突（Symbolic Mismatch）以及移动端声学物理干扰（Plosive Puff）等一系列底层架构难题。本文档详细记录了核心算法模块的重构过程，展示了系统如何通过"双重归一化架构"与"三级声学容错矩阵"，最终实现媲美云端 API 的端侧诊断精度。

---

## 二、 模块一：声学模型选型与端侧部署演进 (Model Evolution)

### 2.1 踩坑：ASR 拼写模型导致的"维度灾难"
在项目初期，推理引擎采用了 `facebook/wav2vec2-base` 模型。系统测试发现，对所有发音均打出 0 分。
* **根源诊断**：该模型为语音转文字（ASR）模型，其底层词表（Vocab）为英文字母（如 A, B, C）。而系统的对齐基准来自 CMU 词典，采用的是国际音标（IPA）。试图用动态规划算法将"字母序列"与"音标序列"进行对齐，属于跨维度的特征不匹配，必然导致全局 Substitution（错读）误判。

### 2.2 重构：切换至专用音素大模型与 INT8 量化
* **模型替换**：选型切换至基于 XLS-R 架构微调的多语言专业音素诊断模型 `vitouphy/wav2vec2-xls-r-300m-phoneme`。该模型直接输出声学层面的国际音素特征。
* **端侧性能优化**：原模型参数量达 300M，PyTorch 原生导出文件高达 1.2GB，极易引发 Android 的 OutOfMemory (OOM) 异常。系统引入 INT8 动态量化 (Dynamic Quantization) 技术，将模型体积压缩至约 300MB，完美适配端侧 ONNX Runtime 推理环境，且推理精度衰减控制在 1% 以内。

## 三、 模块二：信号预处理与 CTC 特征剪枝 (Preprocessing & Pruning)

### 3.1 AGC 自动增益与"防幻觉"拦截
* **痛点**：端侧录音环境复杂，当用户未发声或距离极远时，模型会将纯背景白噪音强行解码为无意义的音素碎片（AI 幻觉）。
* **算法实现**：在音频张量送入 ONNX 推理前，计算 PCM 数据的峰值振幅。
    1. **噪声门槛**：若最大振幅小于 0.015，直接拦截推理，判定为全局漏读。
    2. **自动增益 (AGC)**：若高于门槛，则执行归一化处理，确保微弱的发音特征也能被模型清晰捕获。

### 3.2 CTC 解码去噪与占位符过滤
* **痛点**：Wav2Vec2 采用 CTC (Connectionist Temporal Classification) 贪心解码，输出序列中包含大量非发音特征，如 `h#`（静音帧）、`spn`（环境杂音）以及 `[UNK]`（未知符号）。这些杂质会严重挤占后续的动态规划对齐窗口。
* **算法实现**：在解码循环中硬编码特征过滤器，实时剪枝剔除杂质，确保送入对比算法的数据是纯净的真实音素序列。

## 四、 模块三：核心架构突破——双重归一化 (Double Normalization)

### 4.1 跨服聊天的"巴别塔难题"
在联调过程中出现逻辑冲突：用户读音完全正确，UI 界面上方显示标准音标 `i`，下方显示识别音标 `i`，但系统依然判定为错读（标红）。
* **根源诊断（异构数据源冲突）**：
    * **词典路径（基准）**：遵循语言学家规范，输出高精度的 Unicode IPA（如 `ɹ`, `æ`, `ɔ`）。
    * **AI 模型路径（推理）**：遵循深度学习标注规范，输出 ASCII 变体 Arpabet（如 `r`, `ae`, `ao`）。
    * 算法层由于字符的 Unicode 编码不同（如 `"ɹ".equals("r")` 结果为 false），引发大规模伪错误（False Negatives）。

### 4.2 架构重构：双层翻译机制
系统彻底剥离了"底层比对逻辑"与"表层 UI 渲染逻辑"，引入状态机进行强制转换：
1. **底层降维（Normalize for Compare）**：在 DP 对齐运算前，强制将高精度的 IPA 符号降维为模型理解的 Arpabet 字节码，同时清理所有隐藏空格，确保计算平面特征绝对统一。
2. **表层升维（To Standard IPA）**：在算法对齐完毕、准备返回给 UI 渲染前，拦截输出结果，将底层粗糙的 Arpabet 重新映射为专业的国际音标（如 `ae` 映射回 `æ`，`ao` 映射回 `ɔ`），提供一致且专业的用户视觉体验。

## 五、 模块四：对齐算法与非线性打分映射 (DP & Scoring)

### 5.1 定制化 Needleman-Wunsch 序列对齐

由于用户的发音序列长度通常与标准序列不一致（存在吞音或多读），传统的逐位比对完全失效。系统重写了生物信息学中的 Needleman-Wunsch 全局对齐算法，并对权重进行了精细调优：
* `MATCH = 1.0f` (完全匹配)
* `FLAW = 0.5f` (发音瑕疵，优先级高于错读)
* `MISMATCH = -1.0f` (错读 Substitution)
* `GAP = -1.0f` (漏读 Deletion / 多读 Insertion)
  该权重体系确保了算法在面临错位时，能最大概率地对齐正确的音节，并精准插入占位符防止 UI 错位。

### 5.2 非线性评分曲线拟合
抛弃了生硬的线性百分比计算，引入了基于教学反馈心理学的分段映射函数：
* 准确率 ≥ 0.8：映射至 90-100 分区间（优秀，鼓励性质）。
* 0.5 ≤ 准确率 < 0.8：映射至 60-90 分区间（扩大分数段以体现微小进步）。
* 准确率 < 0.5：严格惩罚区。

## 六、 模块五：声学物理限制与 SLA 容错矩阵 (Error Tolerance Matrix)

### 6.1 物理抗噪：爆破音气流干扰 (Plosive Puff Effect)
* **现象**：用户标准发音 `/k/`、`/p/`、`/t/` 时，模型始终识别为擦音 `/h/`。
* **物理机制分析**：清塞音在发音时会瞬间释放高压气流，近距离冲击手机麦克风振膜，产生非线性物理失真。AI 模型提取的声学特征更接近哈气声，而非声带振动。
* **工程解决**：在底层算法中，硬编码豁免路径（如将 `k` 识别为 `hh` 的情况豁免），在软件算法层面对硬件物理缺陷进行强行补偿，计为完全匹配。

### 6.2 认知容忍：基于 SLA 理论的分级惩罚
参照 Munro & Derwing (1995) 的第二语言习得（SLA）理论，系统将发音评估的重心从"母语者口音（Accentedness）"转移至"可理解度（Intelligibility）"。
* **第一级：完全豁免 (Ignored -> Match)**：针对长短元音细微偏差和清浊音混淆，这些不严重影响英语母语者语义理解的特征，系统直接豁免，给予满分。
* **第二级：发音瑕疵 (Flaw -> 0.6分)**：针对中国学生的典型发音缺陷（如梅花音张口不足，平翘舌不分），系统不判死刑，而是标记为瑕疵并给予部分得分，以保护学习者的自信心。
* **第三级：严重错读 (Substitution -> 0分)**：完全破坏语义的音素替换，扣除全部分数。

## 七、 总结 (Conclusion)

VisionVoice 核心算法的演进，是一个不断在"数字化模型"与"物理世界现实"之间寻找平衡的过程。通过"双重归一化"跨越了符号域的障碍，通过"三级容错矩阵"弥补了硬件麦克风的物理缺陷。这套架构证明了：一个强大的端侧 AI 系统，其核心壁垒不仅在于模型的参数量，更在于对声学物理、数据结构与用户心理的深度工程化解构。
